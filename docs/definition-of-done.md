# Definition of Done (DoD)

The Product Catalog feature is considered done when all applicable requirements for this practical exam are completed and verified.

- [x] Acceptance criteria implemented and manually verified.
- [x] Product documentation completed before the first code commit.
- [x] Express API implements all five required product endpoints.
- [x] API validation and error responses follow the required contract.
- [x] Product list supports search and category filtering.
- [x] Loading, empty, no-results, and error states are handled in the product list.
- [x] Product detail displays all required product information.
- [x] Product creation works against the Express API.
- [x] Product editing works against the Express API.
- [x] Product deletion requires confirmation and returns to the list.
- [x] Product form validates data before submitting.
- [x] Server validation details are displayed when a request is rejected.
- [x] Product prices are formatted using `formatCOP`.
- [x] Stock labels display `Agotado`, `Pocas unidades`, or `Disponible` correctly.
- [x] Kotlin `Product.kt` includes the required model and functions.
- [x] At least two unit tests were added and pass.
- [x] At least two API tests were added and pass.
- [x] `npm test` passes with 10 tests.
- [x] `npm run lint` passes without errors or warnings.
- [x] `npm run build` completes successfully.
- [x] `.env` is not intended to be versioned and `.env.example` is present.
- [x] README explains how to run the API and the Ionic application.
- [x] README includes the required English sections: `State management decision` and `API error handling`.
- [x] Development is performed on `feature/catalogo-productos`.
- [x] Conventional Commits are used during development.
- [ ] Pull Request opened from `feature/catalogo-productos` to `main` in the student's own fork.
- [ ] Pull Request description and final checklist reviewed before submission.
